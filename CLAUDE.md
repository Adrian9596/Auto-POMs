## What this is

**Bra Auto Measure** — a fully offline, single-page browser tool that detects a
bra technical sketch and auto-generates 16 point-of-measure (POM) lines for a
technical designer (TD) to verify. Auto-first (a fork of the "How to measure1"
assistant); after "Apply Lines" it hands off to Manual Mode for TD correction.
No cloud, no API at runtime.

## The one rule that matters most

**Never edit `app.js` directly.** It is generated by `npm run build` from the
files under `src/` (order declared in `scripts/source-parts.mjs`) with the rule
JSON inlined. Editing `app.js` will be silently overwritten.

Workflow for any code change:

1. Edit the relevant `src/*.js` part (find it via the module map in `ARCHITECTURE.md`).
2. `npm run build` — regenerates `app.js`.
3. `npm run check` — rebuild + parse/wiring validation.
4. Run the suite that covers what you touched (see `TESTING.md`).

`src/` parts share one IIFE scope, so a part must appear **after** anything it
references. If you add a new part, register it in `scripts/source-parts.mjs`.

## Commands

```sh
npm run serve    # local server, then open the printed URL
npm run build    # src/* + rule JSON  ->  app.js  (run after every src edit)
npm run check    # rebuild + syntax/wiring checks
npm run smoke    # headless end-to-end Auto Mode run on demo/demo1.jpg
```

Other suites: `golden` (stability), `accuracy` (correctness vs TD ground
truth), `invariants`, `contract`, `pipeline-tests`, `junction-tests`,
`learning-tests`, `meaning-tests`, `evidence-tests`, `autosave-check`,
`export-xlsx`, `export-hidden`, `suggestions-tests` (Tier-0 library-value layer),
`pom7-limitations`. Details in `TESTING.md`. Regenerate the library-value
suggestions with `npm run generate-suggestions` (reads `../Measurements 2`).

## Fixed contracts — change deliberately, not casually

- **The 16 POMs** (`auto_mode_rules/pom-template.json`) and **anchor schema**
  (`auto_mode_rules/anchor-schema.json`) are the versioned source of truth
  (`version.json`). The JSON wins over prose docs if they disagree.
- **Mode behaviour is Auto-first with a Manual handoff**
  (`docs/decisions/0008-reenable-manual-mode.md`): fresh load boots Auto and
  the 16-POM auto pipeline is unchanged; after "Apply Lines" the app switches
  to Manual Mode for TD correction, a visible Manual/Auto toggle allows
  returning, and saved projects with applied lines reopen in Manual. Localized
  to `src/auto/mode.js`, `src/state.js`, `src/project/project-io.js`,
  `src/auto/drafts/draft-actions.js`, the `manual-only` CSS in `index.html`,
  and `src/render/copy-image.js` (Copy Image: whole board → PNG to clipboard,
  offline).
- **Learning never mutates rule JSON.** It only biases anchor seeds, and must
  stay optional, measurable, and resettable.

## Invariants to preserve

- Anchors are normalized `[0,1]` in source-image pixel space.
- Every POM has exactly one review/apply placement view: `front_outer`,
  `front_inner`, or `back`. POM 14 is the measurement-path exception:
  `view: front_to_back`, with `placementViewRole: back`.
- No network call carries sketch or measurement data — offline by design.
- Determinism: the same sketch should yield the same lines (`npm run golden`).

## Conventions

- Vanilla JS, no framework, no build-time bundler beyond the concat step.
- Test hooks are exposed on `window.__braAutoModeDebug` (used by the headless
  suites); don't remove them.
- `demo/*.jpg` are the fixture images; ground truth for accuracy lives in
  `scripts/groundtruth/`.
- Keep changes reviewable: prefer editing one `src/` part and rebuilding over
  broad refactors that reorder `source-parts.mjs`.
